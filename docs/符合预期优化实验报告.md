## 3. 实验一：CRAG 门控阈值标定（H1）— 符合预期

### 3.1 方法

1. 对课程材料建索引，关闭重排，使用稠密余弦分作为命中分。  
2. 运行：

```powershell
python tools/rag_eval.py `
  --docs <KB目录> `
  --eval tools/eval_set_6081.json `
  --grounding-only `
  --target-grounded-precision 0.95
```

3. 在 `grounded precision ≥ 0.95` 约束下扫描 `multi_strong / single_strong / second_support`，比较改造前、只抬 top1、现用组合。  
4. 实现：`rag_api/qa_llm.py` → `classify_grounding()`、`_grounding_thresholds()`。

### 3.2 结果（65 题，余弦口径）

| 阈值组合（multi_strong / single_strong / second_support） | grounded 精确率 | grounded 召回 | 解读 |
|---|---:|---:|---|
| 0.50 / 0.60 / 0.35（改造前） | 0.905 | 1.000 | 召回满分，但假阳性过多（未达 0.95 精确率约束） |
| 0.69 / 0.72 / 0.35（只抬 top1） | 1.000 | 0.754 | 精确率满分，但误杀约 14 道课程题 |
| **0.62 / 0.75 / 0.62（现取值）** | **0.982** | **0.982** | 精确率与召回同时接近最优 |

原始机器结果见仓库根目录 `eval_6081_v5.json`（及同类 `eval_6081_v6.json`）。

### 3.3 机制验证（符合预期的关键发现）

- **判别力主要来自 top2，而非 top1**：切题问题常有多幻灯片覆盖，top2 仍高；跑题问题往往只有一条偶然相似块，top2 明显掉落。  
- 规则「两条证据都 ≥ 0.62」+「单条极强 ≥ 0.75」同时保留了多证据与单证据强命中通道。  
- 单元测试 `tests/test_grounding_gate.py`（含 `test_calibration_prefers_high_precision_threshold`、单命中更严阈值、弱证据走通识等）锁定该行为。

### 3.4 结论

**H1 成立。** 相对改造前，门控在满足高精确率约束的同时保持高召回；相对「只抬 top1」，召回损失显著更小。现用阈值符合「少硬套跑题材料、少误杀课程题」的产品预期。

## 4. 实验二：重排提升证据精确率（H2）— 符合预期（主指标）

### 4.1 方法

控制变量实验：同一评估集前 10 题、同一嵌入 `bge-small-zh-v1.5`、同一混合检索；**唯一变量**为是否启用交叉编码器重排（`ms-marco-MiniLM-L-6-v2`）。

| 条件 | `RAG_ENABLE_RERANK` | 结果文件 |
|---|---|---|
| 基线 | `0` | `docs/rag_eval_6081_report.json` |
| 对照 | `1` | `docs/rag_eval_6081_report_rerank.json` |

端到端链路：建索引 → `hybrid_retrieve` → `run_qa_pipeline` → LLM 五维评审（非桩数据）。说明见 [`rag_eval_6081_report.md`](rag_eval_6081_report.md)。

### 4.2 结果（主指标：context_precision）

| 指标 | 无重排 | 有重排 | 变化 |
|---|---:|---:|---|
| **context_precision** | 0.380 | **0.613** | **↑ +0.233** |

典型题例：第 2 题（考核权重）`context_precision` 从 0.20 → 0.80，无关 Kahoot/Tutorial 片段被挤出前列——与「重排提升证据纯度」预期一致。

### 4.3 重排口径下的门控标定（补充，符合预期）

在 e5-small + MiniLM、`--grounding-only`、65 题上：

| 阈值（multi / single / second） | grounded 精确率 | grounded 召回 |
|---|---:|---:|
| 0.65 / 0.75 / 0.40（旧默认） | 0.980 | 0.877（1 道通识假阳性） |
| **0.80 / 0.80 / 0.60（现取值）** | **1.000** | **0.877（0 FP）** |

数据：`eval_6081_e5_rerank.json`。目标「消除通识假阳性」达成。

### 4.4 结论

**H2 在「证据精确率」维度成立。** 重排完成了其设计本职（抬高 `context_precision`、压低假阳性）。  
> 说明：同次 10 题对照中 faithfulness / correctness 略降，属「部分符合 / 权衡」，**不记入本报告「符合预期」主结论**；见 §9。

## 6. 实验四：会话归属隔离（H4）— 符合预期

### 6.1 方法与实现

- 实现：`rag_api/http_common.verify_session_access`（secret 校验 + 启用鉴权时要求 `user.id == session.owner.user_id`）；无 owner 历史会话由首次访问者认领（`chroma_store.session_set_owner`）。  
- 路由：`rag_api/routes.py` 全部会话端点改用 `verify_session_access`。  
- 前端：对话列表键 `RAG_CONVERSATIONS::<username>`（`ForRag-gh-pages/app.js`）。

### 6.2 测试结果

`tests/test_session_api.py`（含鉴权夹具）实测通过，关键用例：

| 用例 | 预期 | 结果 |
|---|---|---|
| `test_owner_can_access_own_session` | 本人 + 正确 secret → 200 | 通过 |
| `test_other_student_cannot_access_session` | 他人持正确 secret → 403「无权访问」 | 通过 |
| `test_orphan_session_claimed_by_first_visitor` | 无 owner 会话被首访认领，其后他人 403 | 通过 |
| `test_no_auth_mode_still_allows_secret_only` | `RAG_REQUIRE_AUTH=0` 时仅验 secret（兼容本机） | 通过 |
| 既有 secret 错误 / 上传删除等 | 行为不回归 | 通过 |

本机复现记录：`9 passed`（`pytest tests/test_session_api.py -v`，conda `forrag`）。

### 6.3 结论

**H4 成立。** 多学生场景下「知道 session_secret 不等于有权访问」——横向隔离符合产品预期；教师看全班数据仍只走导出中心，不经会话 secret。

## 7. 实验五：导出隐私与默认策略（H5）— 符合预期

### 7.1 产品预期

- 助手页只操作本人会话；学生数据仅经导出主动获取。  
- 导出**不含**完整对话 / 系统回答摘要。  
- 默认可勾选模块以**测验**为主（提问可选）。

### 7.2 实现核对（设计验证）

| 检查点 | 位置 | 状态 |
|---|---|---|
| Schema 默认 `include_quiz=True`，`include_questions=False` | `rag_api/schemas.py` → `ExportRequest` | 已落地 |
| 路由强制 `include_answers=False` | `rag_api/export_routes.py` | 已落地 |
| 前端去掉回答摘要勾选；默认仅勾测验 | `ForRag-gh-pages/export.html` | 已落地 |
| PRD / 流程图与上述一致 | `docs/ForRAG_PRD.md` V2.2 | 已同步 |

测验导出差包含：题干、选项、标准答案、学生作答、正误（见 `export_service.QUIZ_COLUMNS`）；**不含**完整聊天线程。

### 7.3 结论

**H5 成立（产品决策层）。** 该条以「实现对齐决策 + 文档一致」为判据，不依赖 RAGAS 分数；与 §6 会话隔离共同构成多用户隐私边界。

## 11. 总结

在已完成的实验与测试中，下列目标**明确达成预期**：

1. **门控**：在真实 ELEC6081 65 题上取得 grounded **精确率 0.982 / 召回 0.982**，优于改造前与「只抬 top1」方案。  
2. **重排主指标**：同条件 10 题对照下 **context_precision +0.233**；重排口径门控可达 **精确率 1.000（0 FP）**。  
3. **工程与安全**：分块/OCR/缓存/引用/会话隔离均有 pytest 锁定；多学生会话归属隔离实测通过。  
4. **导出隐私**：策略与实现、PRD 一致——默认测验、可选提问、不导出完整对话。
